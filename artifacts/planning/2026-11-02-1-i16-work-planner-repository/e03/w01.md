## Overview

Every theme board and the Initiative template carry a Number field named Priority, holding the rank each numbered priority label carried, so the field is ready before the skill reads it.

## Problem

The boards' Priority field cannot hold a rank.

- **Single-select.**
  Board 17's Priority field is a single-select of High, Medium and Low, and nothing reads it.
- **Labels hold the rank.**
  workflow-server carries `priority: 1` to `priority: 6` and five word labels; m2ux/prosiform carries `priority: 1` to `priority: 9`.

## Proposal

The scene is the user's theme boards, each holding one theme's initiatives and epics, and the Initiative template new theme boards are copied from.

- **The field.**
  Each theme board and the Initiative template has a Number field named Priority, and no Priority single-select. A larger number runs first, and an empty value is no priority.
- **The values.**
  Each open issue's `priority: <n>` becomes its board item's Priority `<n>`, unchanged. A word label moves nothing.
- **The labels stay for now.**
  The labels remain until every installed copy of the skill reads the field.
- **The board artifact states the field.**
  The board artifact's Fields describe the Priority Number field a theme board carries.
