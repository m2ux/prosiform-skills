**Component:** workspace:vendor/prosiform-skills

## Overview

md-composer's installed skill reads the Priority field, and every `priority:` label is then deleted, so the field is the one source of a rank.

## Problem

Labels still carry the rank the field now holds.

- **Two sources.**
  Until they go, a label and a field value can disagree.
- **An older copy reads labels.**
  Deleting them while an installed copy still reads them leaves that copy's queue with no priority, and moves its Ready initiatives to Backlog.

## Proposal

The scene is md-composer, whose submodule pins the skill it runs, and the repositories whose issues the theme boards hold.

- **The pin moves first.**
  md-composer's submodule moves to a prosiform-skills `main` commit whose skill reads the Priority field.
- **Then the labels go.**
  Once that pull request merges, every `priority:` label is deleted from each repository whose issues a theme board holds, and the before-and-after listing is recorded here.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | List each repository the theme boards' items live in, with its `priority:` labels. |
| Plan | Choose the pinned commit. |
| Implementation | Move the pin, merge, then delete the labels. |
| Review | Run Board Queue from md-composer against a theme board after the deletion. |
| Test | `git submodule status` in md-composer and `git grep -n -i -e 'priority label' -e 'priority: *[<0-9]' -- work-planner` at the pinned commit; a label listing of each repository before and after the deletion. |
