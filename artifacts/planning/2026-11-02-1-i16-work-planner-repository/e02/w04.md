**Component:** workspace:vendor/prosiform-skills

## Overview

workflow-server's `workspace` template pins a prosiform-skills commit whose skill reads the Priority field, so every workspace takes that skill at its next update.

## Problem

Until the template's pin moves, the skill every workspace runs still reads priority labels, so the labels cannot go.

## Proposal

The scene is the template's prosiform-skills submodule, which every workspace made or updated from the template follows.

- **The pin moves.**
  The submodule moves to a prosiform-skills `main` commit whose skill reads the Priority field and names no priority label.
- **Workspaces follow.**
  md-composer and every other fork take the new pin through their normal template update.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | Find the first `main` commit holding the field reading. |
| Plan | Choose the pinned commit. |
| Implementation | Move the template's submodule pin. |
| Review | Run Board Queue from a workspace updated to the new pin, against a theme board. |
| Test | `git submodule status` on the template; `git grep -n -i -e 'priority label' -e 'priority: *[<0-9]' -- work-planner` at the pinned commit. |
