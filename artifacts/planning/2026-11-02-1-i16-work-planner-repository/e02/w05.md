## Overview

Every `priority:` label is deleted from each repository whose issues an open theme board holds, so the board's Priority field is the one source of a rank.

## Problem

Labels still carry the rank the field now holds, so a label and a field value can disagree. Deleting them while an installed copy still reads them leaves that copy's queue with no priority, and moves its Ready initiatives to Backlog.

## Proposal

The scene is the repositories the theme boards' items live in, once the template pins a skill that reads the field.

- **No pull request.**
  The deletion changes no branch's code. It is delivered by the before-and-after label listing committed to this record, and the row links that commit.
- **The listing.**
  `e02/priority-labels.md` holds each repository's `priority:` labels before the deletion and the same listing after it.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | List each repository the open theme boards' items live in, with its `priority:` labels. |
| Plan | Record the before listing in this record. |
| Implementation | Delete each `priority:` label, then record the after listing. |
| Review | Compare the two listings, repository by repository. |
| Test | `gh api repos/<owner>/<repo>/labels` for each repository, before and after, recorded in `e02/priority-labels.md`. |
