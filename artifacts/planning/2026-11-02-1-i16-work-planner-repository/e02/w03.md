**Component:** main:work-planner/modes/plan-mode.md

## Overview

Every part of the skill that sets, reads or names a priority uses the board's Priority field, so no rule or script still speaks of a priority label.

## Problem

Outside Board Queue, the skill still names priority labels.

- **Writing.**
  Plan mode saves each confirmed number as the epic's priority label, and Advance mode ensures that label exists.
- **Reading.**
  Deliver mode, the standup report, plan changes and the dependency graph's priority map speak of the label.

## Proposal

The scene is a planning run that confirms an epic's rank with the user, and a delivery or standup run that reads it.

- **Writing.**
  The confirmed number is saved as the epic's board item Priority value.
- **Reading.**
  Every mode, artifact and script names the Priority field where it names a priority.
- **One pull request with the queue.**
  The skill changes how it reads and writes a priority in one merge, so it never holds both.
