**Component:** workspace:.gitmodules

## Overview

In m2ux/prosiform, the workspace that uses the skill takes work-planner from a prosiform-skills submodule pinned to a commit on `main`, linked at the path its agents already load, so the skill runs unchanged from its own repository.

## Problem

prosiform's `workspace` branch holds `skills/work-planner` as the plain copy it receives from workflow-server's template, and nothing records which skill commit that is. Once the template drops its copy, the next template update would leave prosiform with none.

## Proposal

The scene is prosiform's `workspace` branch, whose `.claude/skills` links to `skills/`, and prosiform-skills' `main`, whose root holds `work-planner/` beside the shared guide it links as `../guidelines.md`.

- **Template scripts first.**
  The branch first merges workflow-server's `workspace`, carrying the deploy and update scripts' submodule checkout, so every checkout of prosiform fills the submodule.
- **Submodule.**
  prosiform-skills is a full submodule at `vendor/prosiform-skills`, with no sparse checkout, pinned to a commit on its `main`.
- **Skill link.**
  `skills/work-planner` is a tracked symlink to `../vendor/prosiform-skills/work-planner`, in place of the plain copy. The skill's `../guidelines.md` resolves through it to the submodule's own guide, and its commands' `skills/work-planner/scripts/<name>.py` paths hold unchanged.
- **Before the template's removal.**
  The link merges before workflow-server's template drops its copy, so prosiform never has neither.
- **A new version is a new pin.**
  Taking a later skill moves the submodule to a later `main` commit.
