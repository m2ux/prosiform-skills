**Component:** workspace:.gitmodules

## Overview

workflow-server's `workspace` template takes the work-planner skill from a prosiform-skills submodule pinned to a commit on `main`, so every workspace made from it runs a skill version the template records.

## Problem

The template holds `skills/work-planner` as plain files, which each workspace takes through `update-workspace.sh` and upstream merges, and nothing records which skill commit that is.

## Proposal

The scene is the template's `skills/` folder, which agents load through `.claude/skills`, and prosiform-skills' `main`, whose root holds `work-planner/` beside the shared guide it links as `../guidelines.md`.

- **Submodule.**
  prosiform-skills is a full submodule at `vendor/prosiform-skills`, with no sparse checkout, pinned to a commit on its `main`.
- **Skill link.**
  `skills/work-planner` is a tracked symlink to `../vendor/prosiform-skills/work-planner`. The skill's `../guidelines.md` resolves through it to the submodule's own guide.
- **Same pull request as the copy's removal.**
  The plain copy goes in the merge that adds the link, so no fork of the template has neither.
- **A new version is a new pin.**
  Taking a later skill moves the submodule to a later `main` commit.
