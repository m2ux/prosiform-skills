**Component:** workspace:scripts/deploy-workspace.sh

## Overview

`deploy-workspace.sh` makes a workspace whose submodules stand at the commits its template pins, so a template that takes a skill from a submodule deploys with that skill present.

## Problem

`deploy-workspace.sh` clones the template branch with a plain `git clone -b`, which leaves every submodule empty. A skill folder linked into a submodule would be a dangling link in each new workspace.

## Proposal

The scene is a new workspace deployed from workflow-server's `workspace` template, before any submodule exists in it.

- **Clone with submodules.**
  The deploy checks out each submodule at the commit the template pins, whether it clones the checkout or reuses one already present.
- **Harmless without submodules.**
  A template with no submodule deploys as it does now.
