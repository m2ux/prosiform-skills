**Component:** workspace:.gitmodules

## Overview

md-composer, the workspace in the m2ux/prosiform repository, loads the work-planner skill from a prosiform-skills submodule pinned to a commit on `main`, so the version it runs is one it chose.

## Problem

md-composer's `.claude/skills` is a link to its tracked `skills/` folder, and `skills/work-planner` there is a copy that arrives by merging workflow-server's `workspace`.

- **No version.**
  The copy changes whenever that merge does, and nothing records which skill commit it is.
- **The source goes.**
  Once workflow-server deletes its copy, the next merge of its `workspace` deletes md-composer's.

## Proposal

The scene is md-composer's `workspace` branch, where `.claude/skills` links to `skills/`, and prosiform-skills' `main`, whose root holds `work-planner/` beside the shared guide it links as `../guidelines.md`.

- **Submodule.**
  prosiform-skills is a submodule at `vendor/prosiform-skills`, pinned to a commit on its `main`.
- **Skill link.**
  `skills/work-planner` is a tracked link to `../vendor/prosiform-skills/work-planner`. The skill's `../guidelines.md` resolves through it to the submodule's own guide.
- **One pull request.**
  It merges workflow-server's `workspace`, whose deletion of `skills/work-planner` it takes, and adds the submodule and the link, so md-composer is never without the skill.
- **A new version is a new pin.**
  Taking a later skill moves the submodule to a later `main` commit.
