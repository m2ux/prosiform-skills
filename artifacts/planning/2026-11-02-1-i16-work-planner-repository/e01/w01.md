**Component:** workspace:scripts/deploy-workspace.sh

## Overview

In m2ux/workflow-server, `deploy-workspace.sh` makes a workspace whose submodules stand at the commits that workspace pins, so a workspace that takes a skill from a vendored submodule deploys with the skill present. The template itself declares no submodule.

## Problem

`deploy-workspace.sh` clones the workspace branch with a plain `git clone -b`, which leaves every submodule empty. A skill folder linked into a vendored submodule would be a dangling link in each fresh checkout.

## Proposal

The scene is a workspace deployed from its own `workspace` branch, which may declare submodules under `vendor/` that the template does not.

- **Clone with submodules.**
  The deploy checks out each submodule the workspace declares at its pinned commit, whether it clones the checkout or reuses one already present.
- **Harmless without submodules.**
  A workspace with no submodule deploys as it does now.
