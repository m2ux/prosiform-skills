**Component:** workspace:skills/scripts/check_skill_files.py

## Overview

In m2ux/workflow-server, the `workspace` template drops its plain copy of the work-planner skill, and its shared skill files stop naming it, so the skill has one home and each workspace that uses it links its own copy.

## Problem

The template carries `skills/work-planner` as plain files, and its shared files name it.

- **Shared check.**
  The usage text of `skills/scripts/check_skill_files.py` runs the check over `skills/work-planner`.
- **Shared guide.**
  An example in `skills/guidelines.md` links `work-planner/artifacts/issue-body.md`.

## Proposal

The scene is the template once prosiform's workspace links the skill from its own submodule.

- **The copy goes.**
  Every file under `skills/work-planner/` is deleted. The template adds no submodule of its own.
- **Shared references go with it.**
  The shared check's usage and the guide's example name a skill the template still holds.
- **workflow-canon is untouched.**
  Nothing under `skills/workflow-canon` changes, and its `references/revise-mode.md` still names `skills/work-planner`.
- **How the removal reaches prosiform.**
  prosiform takes the deletion at its next template update. Both sides have deleted the plain files, and the symlink exists only on prosiform's side, so the merge keeps the symlink with no conflict.
- **Each repository owns its shared files.**
  workflow-server keeps its `skills/guidelines.md`, `skills/rules.json`, check script and tests, which may diverge from prosiform-skills' copies.
