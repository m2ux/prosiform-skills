**Component:** main:config/branches

## Overview

prosiform-skills states its long-lived branches, so the skill's branch reads evaluate the repository rather than reporting its names unevaluable.

## Problem

The skill reads a project's long-lived branches from `config/branches` at the commit it evaluates. prosiform-skills has no such file, so a sync, a base preparation or a delivery survey there reports the branch names unevaluable.

## Proposal

The scene is a repository whose task and epic pull requests target `main` and whose planning records live on an orphan `engineering` branch.

- **The statement.**
  `config/branches` at the root of `main` names `engineering` and `main`, one per line.
- **No required criteria.**
  The repository declares no `config/required-criteria.json`.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | Read how the skill's branch reads take the statement at an evaluated revision. |
| Plan | Name the two long-lived branches the repository uses. |
| Implementation | Add `config/branches`. |
| Review | Run the branch read against the epic base and against `origin/main` after merge. |
| Test | `sync.py --names --project <checkout> --revision origin/main` prints `engineering` and `main` and exits 0. |
