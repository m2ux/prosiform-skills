**Component:** main:work-planner/SKILL.md

## Overview

Every command the skill specifies names its script relative to `SKILL.md`, and every procedure runs from the skill's folder, so the commands hold in prosiform-skills and wherever the skill is installed.

## Problem

The skill's commands name their scripts as `skills/work-planner/scripts/<name>.py` from `<workspace>`, the checkout holding the skill. That path holds only where the skill sits under a `skills/` folder.

- **Count.**
  71 occurrences in 22 of the skill's files at workflow-server's `workspace` head.
- **Test.**
  `test_documents.py` finds the scripts a command runs by matching that same path, so it reads no script as run once the path changes.

## Proposal

The scene is one skill read from two places: its own repository, where its tests run, and a workspace that installs it, where its commands run.

- **Scripts are named relative to the skill.**
  Each command names its script as `scripts/<name>.py`, the path relative to `SKILL.md`.
- **Procedures run from the skill's folder.**
  The Conventions section states that every procedure runs from the folder holding `SKILL.md`, and each command runs there.
- **The sandbox stays the host's.**
  `<workspace>` remains the checkout an agent works in, and still supplies `scripts/sbx`. The Dependencies section says so.
- **The test reads the new form.**
  `test_documents.py` matches `scripts/<name>.py` in a command block.
- **Examples move with the layout.**
  A component example naming `workspace:skills/work-planner/...` names `main:work-planner/...`.
