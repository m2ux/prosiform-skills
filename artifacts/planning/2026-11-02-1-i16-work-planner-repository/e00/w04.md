**Component:** workspace:skills/scripts/check_skill_files.py

## Overview

workflow-server's `workspace` drops its copy of the work-planner skill, and its remaining skill files stop naming it, so the skill has one home.

## Problem

workflow-server's `workspace` carries `skills/work-planner`, and its other skill files name it.

- **Shared check.**
  The usage text of `skills/scripts/check_skill_files.py` runs the check over `skills/work-planner`.
- **Shared guide.**
  An example in `skills/guidelines.md` links `work-planner/artifacts/issue-body.md`.
- **Another skill.**
  `skills/workflow-canon/references/revise-mode.md` runs the check and a test suite over `skills/work-planner`.

## Proposal

The scene is workflow-server once prosiform-skills holds a skill that passes its own tests and check.

- **The folder goes.**
  `skills/work-planner` is deleted from `workspace`.
- **References go with it.**
  The shared check's usage, the guide's example and workflow-canon's commands name a skill workflow-server still holds.
- **Each repository owns its shared files.**
  workflow-server keeps its `skills/guidelines.md`, `skills/rules.json`, check script and tests, which may diverge from prosiform-skills' copies.
